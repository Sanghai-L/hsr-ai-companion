# 版本维护手册

D058已在D057关口后完成真实本地组合演练，详见维护就绪关口。它使用测试签名、合成下一版本、可控TTL时钟与合成回执，不替代真实模型或游戏核验。

1. 核对正式游戏来源、版本和许可，列出受影响条目与已有研究。知识只发布数据，程序／规则独立发包；个人研究不直接改公共库。
2. 用独立递增版本构建知识包，运行相关回归，用本机受保护身份签名，更新签名索引。玩家端自动同步只表示与维护者来源一致，不等于覆盖全部最新游戏机制。
3. 玩家再次研究受影响论点时，Agent核对新资料与旧条件，登记证据并提出具体冲突方案。同步器不会理解任意研究正文或自行覆盖旧文；没有玩家回复就保持旧记录。
4. 代码或执行规则改变时构建新的程序版本。检测只保存方案，具体批准绑定目标、包指纹和路径。记录一次可信确认后执行，先暂存、自检及备份，再切换不可变版本。随后重新进入会话加载新版；旧进程继续使用其原代码。
5. 重算旧实验要找到精确匹配且签名有效的原程序快照与原输入。旧快照不可用或被修改时保留历史并拒绝冒充相同方法。更新与回滚不删除新建私人研究。
6. 撤回错误知识时发布更高版本的纠正版，内容可以恢复为此前正确事实；不重写同一版本指纹，不要求客户端信任降级。活跃文件损坏时可恢复上一有效代。
7. 接口字段变化时归类失败并保留旧账号快照，不换未知接口或补造持有。程序异常时先退出占用会话，使用介质 -Action recover／rollback；检查当前数据库与旧程序兼容，不直接还原陈旧研究备份。

每次记录来源版本、程序与知识指纹、测试命令／退出码、原始首次失败和修复复测。私钥、个人原文、UID响应及完整模型轨迹只留本机，公共记录用去敏摘要。正式GitHub Release另按维护者授权执行。

实际演练：知识0.5.0→0.5.1→纠正版0.5.2，程序0.1.3→合成0.1.4→0.1.3；新规则结果12420、原快照结果9720仅为维护测试，不是游戏规则变更。原实验、新旧研究与账号保持，错误接口响应未形成真实网络查询。
