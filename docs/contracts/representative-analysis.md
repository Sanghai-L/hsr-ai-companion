# 代表性比较合同（P4／P5）

方法 `representative-1`。通过 `analysis_schema(mode)` 获取完整合同和对应玩法示例；CLI 与 MCP 共用同一注册表。示例面板是明确假设，不能成为玩家事实。原 `simulation_preflight` 和高精度拒绝分支保留，简化路径有独立的关键缺项检查。

`simulation_compare({request})` 接受2～4个四人候选，共用场景、游戏／数据版本、AV时间窗、初始SP和初始能量比例。默认最多120个动作、4个候选、5秒；硬上限200个动作、4个候选、10秒。全体候选共用计算预算。不同投资口径需要声明，声明后仍不生成排名。并列最优全部返回。

最小构筑只要求角色／形态、等级、明确面板、精确假设速度、轮换、装备实例占用和必要机制。无需填写无关防御／生命、完整遗器词条或敌人AI。面板直接输入，不再叠装备；装备实例仅检查占用，不能据此假装已计算光锥／套装触发效果。当前不自动把真实账号的完整毕业构筑投射为支持状态。

当前数值范围很窄：E0、普攻6／战技终结技天赋10、未解锁大行迹、无秘技和队友指向增益。丹恒支持普攻／战技／按外部减速条件的终结技；黑塔支持普攻／战技高血线加成／终结技／明确跨血线机会的追加。其余清单角色仅支持在被动不触发条件下的普通普攻，不代表完整角色覆盖。米沙同队消耗SP触发的天赋回能未实现时拒绝；云璃有额外储能争议的输入也拒绝。清单和锁定来源哈希见 `manifests/analysis-mechanics.json`。

轮换按精确速度在固定窗口内行动；同AV按队内输入顺序。`after_turn_when_ready` 表示只在本人普通行动后检查是否释放终结技，不是任意时刻最优策略。SP／能量先检查全部成本，再原子结算。省略敌人回合、受击／击杀回能、存活及特殊资源。初始能量按各自上限的相同比例给定，双方会获得不同绝对值，需保留此口径。

目标数、血线、减速和击破前后窗口是共同外部条件；不计算真实HP守恒或转阶段。黑塔跨血线次数必须显式输入，不能由期望伤害自动推导击杀或追加次数。削韧使用普攻30的旧单位，只给弱点匹配的削韧容量；不预测实际击破时刻，不含击破／超击破伤害。阶段分别保留伤害与资源结果。

`completed` 表示本次模型窗口已算完；`resource_deficit`、`actions_budget`、`candidates_budget`、`time_budget`、`cancelled` 都不会生成胜利或排名。关键角色、动作、机制、攻击力或精确速度未知时，伤害为 `null`，保留缺项。仅有部分计算也不能把未计算候选排到最后。

短计算同步返回，无常驻服务、队列或后台战斗进程。库接口提供协作取消回调，CLI可中断进程；本版本不提供异步任务编号、断点续算或完整后端任务提交。输入可重新开始计算。

`comparison_save(account_id, request)` 在现有SQLite事务中保存账号私有的输入、结果、假设、方法／数据／实现指纹；不改账号快照或研究结论。`experiment_replay(account_id, experiment_id)` 检查账号、记录完整性、代码及规则后从头重算，返回 `same_result`；代码或规则变化不能冒充旧方法一致。个人研究可引用这个真实实验ID；既有冲突确认流程保持有效。

`multi_team_plan` 只在明确假设可用清单内枚举少量候选。两半场互斥角色和装备实例；异相三骑士互斥，王棋独立复用。优先改善最弱槽位相对本槽候选最佳输出的比例；不把各场不同口径的原始伤害相加当得分。只声称给定候选集的结果。无合法解返回冲突和替代方向；枚举未结束时不声称无解或最优。

`sensitivity_analyze` 每次1～2个参数，各2～3个值，逐项改变，不做联合网格。支持目标数与阶段乘数／血线／减速，返回具体反转条件；“稳定”仅限已测值，无置信区间。

`current_stage_check` 只读取正式服live入口，冻结真正使用的索引字段、来源日期、哈希和区服。版本标记不证明期数当前；来源排期缺失、时区／区服不明、离线或过期时返回 `partial` 并采用历史／通用条件。参数仅是资料，不从网页执行公式。异相当前期数连接器未接入，明确降级；不能拿通用代表性案例冒充当前关卡。
