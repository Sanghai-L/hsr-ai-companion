# 公开账号导入与修订

`account_configure` 仅保存玩家提供的 UID、区服与交流风格。`account_get`、初始化、知识同步、TTL 到期和任何记忆操作都不会查询 UID。只有 `account_refresh(account_id, request_ref, purpose)` 接受玩家本次明确的 import／refresh 请求，先记录动作，再访问唯一 Enka 公开入口；不登录、不重试、不回退其他服务。

账号资料有三层：不可变原响应、公开字段标准化快照、保留手工覆盖后的有效快照。失败不写空账号；缺字段不清除旧事实，展示移除不推断失去角色。字段来源保留日期，数据缺失仍为 null／unknown。手工资料优先，冲突在导入结果与 account_changes 中可查，不能被远端静默覆盖。

`account_patch` 要求预期快照 ID；远端查询期间若手工资料改变，提交会返回 CONFLICT。有效快照与成功查询动作在同一 SQLite 事务提交。原响应先写入私有文件；崩溃可能留下未生效的观察文件，不会激活半份快照。`account_manual_update` 保留为兼容入口，内部同样检查并发。

服务端 TTL 内的明确刷新返回缓存引用，不再次查询；相同请求引用幂等。TTL 到期本身不赋予权限。公开响应只能证明展示的角色、已装备光锥／遗器及行迹，不证明完整持有、背包、星琼或保底。版本未知时不补为当前游戏版本；没有最终面板字段时不伪造最终速度或二次叠加装备。

Enka 未提供背包实例身份，装备 instance_id 只是展示观察 ID。旧观察可因未展示而保留，应按字段日期和当前展示范围解释，不能直接作为完整且实时的装备分配输入。精确实例去重和模拟所需数据由后续覆盖检查阻断。

真实接口验收只使用 D006 文档作者公开样例，一次导入验证 avatarId、enhancedId、level、promotion、rank。其他区服和游戏内精度尚未实测。原始身份、响应和私有测试授权保存在 .local，不写入共享 fixture。
