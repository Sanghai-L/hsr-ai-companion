# 个人记忆、冲突与确认

事实／偏好、讨论摘要、假设、研究结论保存在账号私有 SQLite 索引与不可变 Markdown 正文中。核心格式独立于宿主私有记忆。事实需来源与事实依据；假设保持 hypothesis，不修改账号快照。结论需稳定 claim_key、实体／版本、适用条件和证据或实验引用。相同键与范围的不同结论通过追加入口会返回 CONFLICT，不会静默替换；语义等价但不同键仍需 Agent 根据证据识别并主动提出冲突。

检索按账号、主题、实体与版本过滤，默认只返回当前有效记录的摘要与正文引用。未知版本不会自动补为当前版本；未指定版本时各条保留自己的范围。完整历史可用 memory_read 分页读取。上下文按实际序列化字符预算选择摘要；正文与索引指纹不一致则报告冲突并保留文件，恢复不删除研究。

新证据先登记，再用 memory_conflict_propose 生成冲突与具体 replace／restrict／retract 方案。旧正文不变；检索自动附待处理冲突。方案绑定账号、旧记录 ID、旧文件指纹、修订次数、精确新正文、条件与新证据。memory_revision_get 可完整审阅。

确认必须关联可核验玩家回复。普通 MCP 参数、confirmed=true 和模型自行引用的消息不构成该记录。可信宿主转接器可调用进程内 record_verified 并提供实际回执验证器；目前 Codex 未提供这种原生业务回执接口，交付可用的本地交互入口：`python -m companion --data-dir <玩家目录> confirm-revision --account <账号> --plan <方案>`。该入口展示具体方案，仅记录一次确认，不自行执行；随后 memory_revision_apply 消费对应记录。玩家无须为同一方案再次确认。

自动化验收的宿主脚本用独立于 Agent 的实际脚本玩家消息创建绑定回执，明确标为受控测试适配，不冒充 Codex 原生能力。运行时不启用测试确认后门、不提供自我确认 MCP 工具。

修订先写历史文件，再事务切换当前指针并记录确认引用。重复执行同一方案返回原结果；旧版本发生变化拒绝旧方案。崩溃留下的修订正文可恢复为历史文件，不会自动激活。废止后默认检索不使用该结论，历史正文仍可读。正文历史不会被覆盖。
